02

Архитектура

Ядро не содержит UI и не обращается к платформенным API: только std, serde, serde_json, thiserror. Направление зависимостей одностороннее: оболочка → биндинги → ffi → core.

оболочка Android (каталог · плеер · приёмка) │ JNI: app.obereg.core.CoreBridge ▼ CoreSession ──► TransportRouter ──► DirectTransport │ │ │ │ │ └────────────► TunnelTransport ──► LoopbackTunnel (SOCKS5) │ ├──► CatalogSource (local · сетевой — точка расширения) │ │ └──► Journal (JSONL) · StateSnapshot upstream: direct | socks5 | http_connect ▼ плеер Media3 ── OkHttp (SOCKS через ядро) ──► видеопоток
Модули ядра
МодульОтветственность
errorтип ошибки и Result
configконфигурация, режимы, upstream, валидация
extractразбор ответа видеосервиса и выбор потока для своего плеера
catalogисточник каталога, элемент видео, поиск
journalJSONL-журнал с непрерывным seq
stateсостояние и наблюдатели
transportпрямой и туннельный транспорт, откат
tunnelлокальные SOCKS5 и HTTP CONNECT прокси, восходящий узел
sessionфасад: жизненный цикл, статус, проба, каталог
Туннель живёт внутри процесса приложения: нет конфликта «один VPN на систему», нет системного разрешения, на ПК не нужны драйверы.
Каталог и плеер общаются только с ядром. Замена локального источника на сетевой (извлечение потоков у видеосервиса) не потребует правок в оболочке.

Осталось и как воспроизвести

Открытые пункты:

  • за вами запуск APK на телефоне: adb install -r DELIVERY/obereg-debug.apk, затем «Автотест» → «Каталог видео» → выбрать видео → «Через туннель».
  • позже прогон CI в удалённом репозитории (ссылки на сборки) и baseline с раннера.
  • позже сетевой источник каталога — нужен доступ к видеосервису.

Проверить самому:
